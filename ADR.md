# ADR.md — AlAzharTex decision records (binding, see RESOLUTIONS.md for contradiction rulings)

## ADR-001 — Offline-first, single source of truth = on-device Room (SQLite)
Every feature works with zero connectivity. Backups are explicit user exports (VACUUM INTO +
sha256 sidecar), never cloud sync. The APK requests NO INTERNET permission.
Consequences: CSV/share exports scoped via FileProvider to `exports/` only; import is a
destructive-with-consent flow behind a five-rung integrity ladder (see ADR-004).

## ADR-002 — Deterministic seed, generated once, verified everywhere
`seed-alazhartex.json` is generated by `:generator` (xorshift64*, UUIDv5 DNS+"alazhartex.seed",
canonical JSON, fixed clock 2026-01-05T09:17:00Z +41min). It is committed with
sha256 a71988826a28ef283c36f5dad91c214617ec53f010fa53d7b86220272e511fe6 and pinned in CI.
No number in the app is typed by hand; §4.2 numbers come from `seed-report.txt` via three
oracles (O1 generator assertions, O2 `tools/independent_checks/spec_oracle.py`, O3 Python
mirror + `audit_checks.py` D19).

## ADR-003 — Derived opening, cached but checked (RES-021)
Anything displayable on inventory rows: `opening` is DERIVED (`closing − Σmovement deltas`).
Room persists `closing` and a transaction-bound `opening_cache`; every mutation re-derives
and rewrites the cache inside the same transaction, and a post-transaction audit query
(`driftRows()`) must return zero rows on the seeded data (it does; CI D-gate: `audit_checks`
+ Room recheck). CSV exposes both `opening` (derived at export time) and `closing`.

## ADR-004 — Import = five-rung ladder, preview, explicit overwrite, safety copy
R1 sha256 vs sidecar (REQUIRED; missing/malformed sidecar refuses the import), R2 SQLite
magic, R3 `PRAGMA integrity_check` == ok on the candidate BEFORE any swap, R4
`application_id == 1096438856` ('AZTH') + `user_version == 1` + `PRAGMA foreign_key_check`,
R5 per-table `_manifest` row-count match. On Ready: preview counts are shown and the user
confirms the overwrite explicitly; `safetyBackupAndReplace()` keeps the three most recent
`safety-<ts>.db` copies in `files/backups/` (prune log outside the DB). After a successful
swap the process relaunches because Room cannot hot-swap its backing file.
Zero dials in between: no silent fallback, no 1-rung imports, no in-place edits.

## ADR-005 — Sessions without a login screen (admin auto-session)
The seeded ADMIN account is auto-signed-in on cold start; foreground resumes >1 min old
silently re-issue the admin session (audited `session.reissue` / `session.refresh`), keeper
sessions are strict (expired ⇒ mutation refused with `session.expired`). Wall clock moved
backwards >5 min ⇒ `SESSION_CLOCK_ANOMALY` refusal for ANY role, audited BLOCKED. Mutations
additionally refresh the admin session silently every 12 h during active use.
`boot_id` (persisted per process) + `ELAPSED_REALTIME_WAKEUP` elapsed time disambiguate
device reboots from clock skew.

## ADR-006 — Atomic conditional decrement for stock removal (T5)
Negative stock is refused by an atomic `UPDATE inventory SET closing = closing − :qty
WHERE mapping_id = :id AND closing − :qty >= 0`; `rowsAffected == 0` ⇒ ShortfallException
with the re-read available count. Read-check-write never happens outside the transaction.
Transfers are TWO legs of ONE transaction (conditional decrement on source, increment on
target, one UUID `transfer_pair_id`), so a mid-flight crash cannot lose rolls (C1).

## ADR-007 — RBAC verdicts live in domain/, enforced in repositories, audited
`domain/Rbac.kt` holds the 27-row truth table (ADMIN / KEEPER / SALES_MANAGER ×
read/write/masters-add/masters-delete/regrade/settings/export/import). Every refusal —
RBAC, session anomaly, shortfall, invariant — is written to `audit_log` with
`result = BLOCKED` and a `reason`; `result = ALLOWED` only when the mutation applied.
Keepers: read all, write assigned 5 sheds, masters ADD-only. No settings, no export/import,
no delete/regrade. Sales manager: read-only everything.

## ADR-008 — Gauge thresholds pinned (§9.3)
<50.00% GREEN · 50.00–85.00% AMBER (inclusive) · >85.00% RED · 2dp HALF_UP for bucket math ·
display percent drops trailing zeros ("175.2", "50", "85") · `closing == 0` ⇒ "0" GREEN ·
`capacity == 0` ⇒ "—". Thresholds live in `domain/gauge/Utilisation.kt` only.

## ADR-009 — CSV: BOM exactly once, formula-injection escaping (§9.13)
`domain/csv/Csv.kt` builds documents: one U+FEFF at file start; leading `= + - @ TAB CR LF
space` cells get a `'` prefix; column sets come ONLY from `CsvColumnSets` (CONTENT.md §6).
Note: a formula-injection prefix (`'=x`) does not byte-round-trip a naive CSV parser that
ignores the escape convention — documented here as accepted, one-directional; the
round-trip test covers values without the escape.

## ADR-010 — Digits: Western by default (§9.21)
`NumberFormat.getIntegerInstance(Locale)` with `en-US-u-nu-latn` default; Arabic-Indic
digits only behind the Settings toggle (default OFF), persisted in `app_settings`
(`arabic_indic_digits`). Dates `yyyy-mm-dd`; "today" = `Africa/Cairo`.

## ADR-011 — Manual DI, no Hilt
One `AppContainer` (Application-owned), `by lazy` singletons, coroutine scope tied to the
process. Zero code generation beyond Room/KSP; the dependency graph is auditable in one file.

## ADR-012 — Audit retention, export manifest, prune logs outside DB
`_manifest` (table_name, row_count, schema_version, app_version, exported_at) is rewritten
inside the export transaction and checked at import R5. Safety backups keep 3; pruned names
are logged to `files/backups/prune.log` (never inside the DB being replaced).
